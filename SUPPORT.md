# Support

## How to get help

This project uses GitHub Issues to track bugs and feature requests. Before
opening a new issue, please search the existing ones to avoid duplicates.

- **Bug reports:** use the *Bug report* issue template and include the steps to
  reproduce, what you expected, what happened, and the commit you were on.
- **Feature requests:** use the *Feature request* template and describe the
  photographer's problem before the proposed solution; requirements in this
  project are expressed as acceptance criteria (see
  [`docs/specs/L2.md`](docs/specs/L2.md)).
- **Questions about running Loupe:** start with the guides —
  [`README.md`](README.md), [`backend/README.md`](backend/README.md),
  [`frontend/README.md`](frontend/README.md),
  [`design-system/README.md`](design-system/README.md) and
  [`docs/demo/README.md`](docs/demo/README.md) — then open an issue if the
  answer is not there.
- **Security issues:** never file them publicly; follow [SECURITY.md](SECURITY.md).

## Support policy

Loupe is maintained on a best-effort basis by its author and contributors.
There is no commercial support or guaranteed response time. Well-written issues
with reproductions and pull requests with acceptance tests are the fastest route
to a fix.
